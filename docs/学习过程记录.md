## 2026-05-15（Day 2）

### 已完成
- **Vision Transformer（ViT）原理 — 完整讲解**
- **EMA（指数移动平均）**
- **L1 vs L2 Loss**

### 核心要点

**1. 图片 → Patches → Tokens**
- 224×224 图片，切成 16×16 patches → 14×14 = 196 个 patch
- 每个 patch 拉直为 768 维向量（3×16×16 像素值）
- 通过 Patch Embedding（一个 Linear 层）映射到 Transformer 工作维度（如 1024 维）
- 这 1024 维是**学习到的特征**，不是原始像素，模型自己学会从杂乱像素中提炼有用信息

**2. 位置编码**
- Self-Attention 是排列不变的（交换 token 顺序结果不变），必须注入位置信息
- V-JEPA 默认使用 **RoPE（旋转位置编码）**：在 Attention 计算时通过旋转 query/key 向量来编码位置
- RoPE 优势：自然支持变长/变分辨率输入

**3. 从 2D 图片到 3D 视频**
- 视频多了时间维度：(3, T, H, W)
- PatchEmbed3D：空间上切 16×16，时间上用 tubelet_size=2
- 16 帧输入 → 8 个时间步 × 14×14 = **1568 个 token**

**4. Transformer Block**
- 每个 block：LayerNorm → Multi-Head Self-Attention → 残差连接 → LayerNorm → MLP (SwiGLU) → 残差连接
- Self-Attention：每个 token 问所有其他 token "你和我的内容相关吗？"
- ViT-L 有 24 层，ViT-g 有 40 层

**5. ViT 在 V-JEPA 中的角色**
- Encoder 就是一个 ViT，只处理**可见的 token**
- 输出的特征传给 Predictor，Predictor 用可见特征预测被遮罩区域的特征

### 讨论过的重点问题
- 196 个 token 的计算：224÷16=14 个/边，14×14=196
- 每个 token 的 tensor 形状：(196, 1024) — 196 个 token，每个 1024 维
- 原始像素作为 token 是否太杂乱 → 实际输入 Transformer 的是**经过 Linear 层提炼后的特征**，不是原始像素
- 16 帧是否每一帧都必要 → V-JEPA 通过**遮罩策略**迫使模型只抓关键信息，训练模型像人一样稀疏地理解视频
- ViT 命名规范：B=Base(86M)、L=Large(300M/24层)、H=Huge(630M)、g=giant(1B/40层)、G=Gigantic(2B/48层)。字母越往后参数量越大，层数、向量维度、注意力头数同步增加

#### 补充概念

**6. EMA（指数移动平均）**
- Target Encoder 通过 EMA 从 Online Encoder 缓慢复制参数：`param_target = 0.99925 × param_target + 0.00075 × param_online`
- 作用：提供一个稳定的目标，防止模型坍塌
- 类比：学生对错题快速调整（online），老师通过长期观察稳定吸收（target）

**7. L1 vs L2 Loss**
- L1 = 绝对值误差，L2 = 平方误差
- L2 对大误差极度敏感，L1 更鲁棒
- V-JEPA 选择 L1：特征空间可能出现异常值，L1 避免异常维度主导梯度

#### 讨论过的重点问题
- EMA 全称：Exponential Moving Average（指数移动平均）
- 为什么需要两个编码器：防止模型「作弊」——如果自己预测自己，会坍塌到恒定输出
- 为什么 V-JEPA 选 L1：特征空间预测的本质需求——对异常值不敏感、训练更稳定

### 已完成
- **张量形状追踪**（实战）— `trace_tensor_shapes.py`，验证 224×224 视频 → PatchEmbed3D → 24 层 Block → 输出全程形状不变
- **推理全流程实战**（实战）— `run_inference.py`，跑通 Encoder → Predictor → Loss 完整数据流
- **3D 遮罩策略 **（理论+代码）— 读完 `multiseq_multiblock3d.py`

### 核心要点

**1. 张量形状追踪关键发现**
- 输入 `(1, 3, 16, 224, 224)` → PatchEmbed3D → `(1, 1568, 1024)`
- 之后 24 层 Block 形状**全程不变**：Transformer 做值的变换而非形状变换
- 305.5M 参数中绝大多数在 MLP 层（每层 `1024→4096→1024`）

**2. 推理全流程数据流**
```
视频 (1, 3, 16, 256, 256) ──► Encoder(加遮罩) ──► 820 个可见 token
                                        ├──► Predictor ──► 1228 个被遮 token 的预测
                                        └──► Target Encoder(全量) ──► LayerNorm ──► 1228 个目标
                                        └──► L1 Loss（预测 vs 目标）
```
- Encoder 总参数量：303.9M（ViT-L）
- Predictor 总参数量：11.4M（6 层 Transformer）
- 随机权重下 L1 Loss ≈ 0.86

**3. 3D 时空遮罩策略**
- 文件：`src/masks/multiseq_multiblock3d.py`
- 两个类：`MaskCollator`（顶层调度）→ `_MaskGenerator`（实际生成）
- 遮罩在 **patch 空间**操作，网格大小 = `(T/tubelet, H/patch, W/patch)` = `(8, 14, 14)`
- 生成流程：
  1. `_sample_block_size` — 随机采样遮罩块的三维尺寸（时间尺度 × 空间尺度 × 宽高比）
  2. `_sample_block_mask` — 在 3D 网格上随机放置遮罩块（对应位置置 0）
  3. `__call__` — 对每个样本放 npred 个块并取并集，分出 pred_mask（被遮）和 enc_mask（可见）
  4. 截断到 batch 中最短长度，拼成 tensor
- 配置示例（2 层）：8 个小块（15% 面积）+ 2 个大块（70% 面积），全部时间步共享

![V-JEPA 场景变化预警架构图](../demo_forecast.png)

### 核心要点

**1. V-JEPA 不是预测模型**
- V-JEPA 的训练方式确实是"做预测"（遮罩→特征空间预测），但这是手段不是目的
- 学出的特征向量才是真正有用的东西
- 类比：BERT 训练做"完形填空"但不是填词工具，学出的词向量才是价值所在

**2. V-JEPA 在自动驾驶链路中的位置**
```
视频帧 → V-JEPA Encoder (冻结) → 1024维特征向量 → 上层模型 → 预测/分类/检索
         ↑                            ↑                          ↑
     预训练, 不更新              语义特征                  你训练的小模型
```

**3. 特征变化率作为预警信号**
- 相邻片段特征余弦相似度的变化 = 场景"变化速度计"
- 相似度骤降 → 场景正在切换
- 这个信号往往在视觉明显变化之前就开始上升
- 自动驾驶应用：提前 0.5-1.5 秒感知"前方场景要变"

### 讨论过的重点问题
- 为什么"根据图片找相似图片"不是 V-JEPA 的核心用途 → V-JEPA 学出的是通用特征，检索只是应用之一
- 预测未来和特征提取的关系 → V-JEPA 提供特征表示，真正的时序预测需要额外模型
- 视频太平滑导致分类测试集全是一个场景 → 改用"变化率预警"方案更合适
- 非重叠 vs 重叠采样的区别 → 非重叠避免"共享上下文"的假匹配，重叠得到更平滑的变化信号

- **V-JEPA 2 vs V-JEPA 2.1 差异对比**（源码级分析）
  - **Dense Features（密集特征）**：2.1 从 4 个深度层 [9,19,29,39] 分别输出特征并拼接 → 维度从 1024 变为 1024×4=4096（ViT-L）
  - **ImageNet 联合训练**：在视频批次中混入 ImageNet 图片，按相同遮罩流程训练
  - **Context Loss（上下文损失）**：额外计算未遮罩区域的预测和目标之间的双向对齐损失
  - **模型规模扩展**：新增 ViT-B（Base）和 ViT-G（Gigantic，~2B 参数）
  - **代码位置**：`app/vjepa_2_1/models/` 独立于 `src/models/`

- **V-JEPA 2-AC（动作条件预测）**（源码级分析）
  - 核心区别：Predictor 额外接收**动作向量**和**状态向量**作为条件
  - 结构：`action_encoder = Linear(7→1024)`，`state_encoder = Linear(7→1024)`
  - Token 排列：每帧 `[action_token, state_token, patch_0, ..., patch_N]`
  - **因果注意力（Causal Attention）**：通过 `ACRoPEAttention` + frame-causal mask 实现，当前帧只能看过去帧
  - 训练：Teacher-Forcing（用真实动作预测下一帧特征）+ Auto-regressive 损失
  - 应用：机器人操作，给定未来动作序列可预测视觉结果
  - 数据集：DROID（HDF5 存状态 + MP4 视频，7 维动作空间）

- **V-JEPA 2 训练硬件需求**
  - ViT-L 配置：16 nodes × 8 GPUs = **128 GPUs**，每 GPU 220G 内存
  - 数据集：K710（33.5%）+ SSv2（10.0%）+ HowTo100M（56.5%）
  - batch_size=24/GPU，bfloat16，NCCL 分布式，10 epochs
  - 实际中小团队方案：使用预训练权重做下游任务微调，不需从头训练
